# Zzp Sub 1.1 重构说明

评估基于 MiSub 的实际 Vue 源码、Home 的 `tokens.css`、`base.css`、`layout.css`、`motion.css` 与 `AppShell.tsx`，以及本地合成数据下的浏览器渲染。Home 仅作只读参考，没有改动其代码或云资源。

## 设计取舍

| 项目       | 实际评估与本次处理                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------ |
| 信息层级   | Home 的标题、工具栏与内容分工更清楚；Sub 移除标题卡片和重复设置模块标题，保留数据和操作密度。          |
| 留白       | 采用 16/24/32px 为主的间距，窄屏压缩边距。仪表盘只在有待办时展开详细状态，减少多次宣告正常。           |
| 卡片与阴影 | Sub 的订阅卡片便于查看流量、更新与节点，保留；工具栏、机场分组及基础设置改用分隔和留白，降低卡片嵌套。 |
| 字体       | 借鉴 Home 的系统字体栈，移除外部 Google Fonts、预连接和字体阻塞请求。表单仍使用足够的输入字号。        |
| 配色       | 保留 Sub 已有冷色靛蓝与深浅主题，状态色只承担警告或操作含义，不复制 Home 的暖色主题。                  |
| 圆角       | 保留 Sub 原有 6/8/12px 层级并使用统一变量，导航保持紧凑。                                              |
| 导航       | 保留适合五个后台模块的顶部导航与移动底栏，移除旧布局切换与重复设置入口；增加当前页语义和跳到内容入口。 |
| 动效       | 移除登录悬浮装饰、统计卡延迟和 Toast 微光，弹窗使用 160/220ms 节奏与轻微位移，保留减少动态效果偏好。   |

## 页面与架构

- 只保留 `App.vue` + 独立视图这一套后台，删除旧 Dashboard、Header、设置弹窗、未引用组件、无用桶导出与工具。
- 机场分组的指定、拆分与恢复操作放入菜单，搜索自动展开命中分组，320px 下无横向溢出。
- 手动节点默认列表，保留用户保存的视图选择、分组、搜索与批量工具；编辑及导入弹窗按需加载。
- 设置只加载当前栏目，保存后更新内存配置，避免整页重载和丢失其他页面草稿。
- 会话检查只请求一次 `/api/data`，删除已废弃的登录路径查询。
- 不在浏览器存储中复制私密业务集合。登出清除内存，迟到响应不重新注入；保存期间的新编辑不会被旧响应覆盖。
- 移除旧登录配置、KV/D1 迁移接口、D1 数组主行回退和读取时自动改写 profile ID 的实现。生产只读检查确认当前集合已经是行级格式，数据库未执行迁移。旧 NodeTransform 的编辑迁移与运行时桥接也已删除；全局与订阅组使用统一规则链。
- 删除重复中文 README、旧升级指南、历史评审与旧截图；保留 LICENSE、NOTICE 和贡献者署名。

## 性能与验证

同一本机 Node.js 24 下，原始构建的主 CSS 为 194.86 kB（gzip 26.32 kB）；重构后约 165.51 kB（gzip 23.89 kB）。入口 JS 从 188.85 kB（gzip 65.23 kB）降到约 179.21 kB（gzip 62.51 kB）。这些是构建体积，不冒充线上加载耗时。

源码引用图从 216 个 JS/Vue/CSS 模块缩减到 165 个，当前均从入口可达。移除 terser 与 jsdom，锁文件依赖包减少 51 个；Vite 使用自带 esbuild 压缩。重型弹窗及设置栏目按需加载，原 118.23 kB 的设置整包不再一次性加载。

回归覆盖认证、Token、D1、快照、自动刷新、备份、转换和前端状态；浏览器使用合成数据验证 1280/820/390/320px、五个页面、搜索、设置栏目、节点新增保存、设置保存、退出及深色主题。另以真实 Mihomo 与 sing-box 校验 40 份完整合成配置。

## 发布边界

继续使用 Vue 3 与原 Cloudflare Pages、D1、KV、Secrets，不引入 Zero Trust，不创建预览云资源，不改动生产业务数据。按用户要求不保留旧域名别名或重定向；新域名可用后停用旧入口，客户端需重新导入新域名链接。发布状态和线上验证结果单独记录在交付报告中。
