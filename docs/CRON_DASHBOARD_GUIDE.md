# MiSub 外部定时刷新使用说明

> 当前 MiSub 运行于 Cloudflare Pages，**不会仅因填写 Cron Secret 就自动定时执行**。无需打开浏览器的主动更新，需要另设外部定时请求（或部署其他可信调度器）。

## 运行机制

- 日常客户端拉取 MiSub 时：使用每个来源的永久快照；已有快照过期时，按订阅源配置尝试后台更新，失败继续提供上次成功的节点。
- 外部访问 `/cron` 时：调用与客户端相同的安全刷新服务，按来源自动更新开关、间隔和失败重试退避条件筛选任务。
- 每个来源的节点、流量信息及节点数量来自同一次有效的上游响应，不再由旧版计数脚本另行覆盖。
- 手动「刷新来源」按钮仍可主动刷新该来源，与 Cron 共用快照存储。

## 配置步骤

1. 在「设置 → 服务集成 → 高级设置 → 外部定时刷新」设置随机的 `Cron Secret` 并保存。
2. 在你的外部定时调度服务中添加一次带认证的 HTTPS 请求，访问 `https://misub.zzp.moe/cron`。
3. **优先使用** HTTP 请求头 `Authorization: Bearer <Cron Secret>`。仅当服务无法发送请求头时，才使用页面生成的 `?secret=...` 兼容链接；避免将含密钥的 URL 贴入日志或公开分享。
4. 按上游订阅允许的频率设置触发，例如每 60 分钟一次；是否真的拉取上游由各订阅源的 `autoUpdateEnabled` 和 `autoUpdateIntervalMinutes` 决定。

注意：用户已经配置的每来源自动更新开关及间隔是权威设置。关闭自动更新的来源不会被 Cron 强制刷新，但可从管理界面手动刷新。

## 接口及权限

| 接口 | 认证 | 用途 |
| --- | --- | --- |
| `/cron` | `Cron Secret`，Bearer 或兼容 query 参数 | 外部调度触发持久快照更新 |
| `POST /api/cron/trigger` | 已登录管理员 Cookie | 从管理 API 手动运行相同的更新 |
| `GET /api/cron/status` | 已登录管理员 Cookie | 查看手动触发状态（若有记录） |

`/cron` 响应包含 `total`、`updated`、`skipped`、`failed`、`preserved`：失败时旧节点缓存仍会保留。

旧版 `/_cron`、`/_schedule`、`/cron-dashboard` 是无效或模拟实现，已移除。它们不适合作为长期调度入口。

## 与订阅客户端的关系

MiSub 负责上游订阅管理、快照缓存和分发；不同客户端仍可自由设置自己的拉取间隔。**客户端拉取缓存不需要直接访问机场或 VPS**，并非每次都会触发上游请求。
